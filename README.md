# ごちそうカンパニー v59

畑から、工房から、みんなの食卓へ。スマホ縦画面を中心に遊ぶ食品会社経営シミュレーションです。v52を調査したうえで、ゲームの状態管理と画面を作り直しました。

## スマホで遊び始める

**Android・iPhoneとも、ブラウザ版のURLをChrome・Safariで開く方法が基本です。**

ブラウザ版： https://gochisou-company-mobile.dandeeeee.chatgpt.site

この版は作成者本人のアカウント向けです。サイト側でログインを求められた場合は、このゲームを作成したChatGPTアカウントで開いてください。ゲームのセーブは端末・ブラウザ内に保存され、アカウント間・端末間の自動同期はありません。

### Androidでファイルから開く場合

1. ZIPを展開し、`index.html` をChromeなどJavaScriptを実行できるブラウザで開きます。
2. v59の `index.html` はCSS・JavaScript・イラストを内蔵しています。同じフォルダーの別ファイルを読めない `content://` でも、外部ファイルの欠落による白画面を避ける構成です。
3. 保存領域が利用できない場合は「保存しない一時プレイ」を選べます。終了前にJSONまたは文字コピーでバックアップを保管してください。

ファイル閲覧アプリがJavaScript自体を実行しない場合は、単一HTMLでも遊べません。起動画面に残る「ブラウザ版を開く」からHTTPS版へ移動してください。実際のAndroid `content://` での動作は端末未確認です。

### iPhoneで開く場合

Safariで上記ブラウザ版URLを開いてください。ファイルアプリや添付ファイルのプレビューからのゲーム実行は保証しません。Safariの共有メニューからホーム画面へ追加する使い方もできますが、オフライン起動は保証しません。ローカルHTMLの保存状態はHTTPS版へ自動移動しないため、移動前にバックアップを書き出してください。

### 自分のWebサイトへ置く場合

`index.html` 1ファイルだけをHTTPSの静的ホスティングへ置けます。ゲーム実行時に外部ライブラリ・CDNは不要です。PCで試す場合は展開したフォルダーで `python3 -m http.server 8000` を実行し、`http://localhost:8000` を開けます。

分割ソースは保守・テスト用に同梱しています。変更後は `python3 tools/build.py` で `index.html` を再生成してください。

## 最初の一日：みのりの操作案内

ホームの一番上に「次に押すボタン」を1つ表示します。最初は、受注 → 小麦粉3個 → パン3個 → 納品 → おまかせの5段階。材料・数量を入力画面に引き継ぎ、作業すると案内が次の工程へ変わります。初回注文は品質Eから達成でき、抽選だけで失敗しません。

納品できたら「受注後の準備と納品を任せる」を選べます。以後は注文を自分で選び、「翌日へ」で費用・納品予定を確認して閉店。必要な収穫・加工・納品を1日1,200円と残り作業枠の範囲で実行します。毎日の手動収穫は必須ではありません。

一括製造・納品を先に使っても案内は進みます。案内は省略可能で、「その他→設定→操作案内を再開」から現在の会社で再開できます。既存セーブでは初回案内を強制しません。

## 納品数の増やし方（v59）

ホーム・注文画面の「増やし方」を押してください。

- パン3個の注文を完了すると **1件・3個**。作るだけでは納品実績になりません。
- 加工研究：一度に作れる個数を増やす。標準の最初の研究は3→4個、22P。
- 工房増築：一日の加工枠を増やす。通常は5→6枠、初回1,200円。使用済み枠は戻りません。
- 販売研究：Lv2/4/6で同時受注枠＋1。Lv3/6で一日の新規受注上限が3→4→5件。
- 量産や職人の加工能力・特技でもバッチ数を増やせます。品質との違い・代償を画面で比較できます。

投資は全部買う必要はありません。現在値と投資後の効果、必要費用を見て選べます。受注済みの個数・報酬・期限は変更されません。旧セーブの過去の納品個数は復元できないため、件数を保持し、個数は「更新後」の集計と表示します。

## 数日先の楽しみ：町からのお便り（v59）

3・7・12・18・26・37・48・56日目を目安に、常連の8通の便りが届きます。一度に1件。未読の便りは回答まで残るため、後続は順番待ちになります。

まとまった注文に応えるか、工夫のヒントを聞いて献立・研究・地域・看板商品・大会に進むかを選びます。ヒントは各便りにつき研究P12を1回だけ。注文はまず候補に追加され、実際に受注してから4営業日の期限が始まります。候補は通常どおり翌日に更新。未解放の商品は作れる基礎商品へ置き換え、実際の商品名を表示します。挑戦案件の品質条件も選択前に表示します。

ホームには「次の一歩」「近い目標」「長期目標」を優先して表示。詳しい余力と閉店予定は折りたたみ、全機能を毎日触る必要はありません。最初の地域目標は町内8件の納品。実績により記念看板と会社経験10を獲得します。

大会で出品在庫がない場合は、材料から1個だけ準備するボタンを表示します。費用・作業枠を確認して製造した後、品質と予測点を見てから別操作で提出します。

## 注文の「次にすること」（v58）

注文カードに、不足している条件と次のボタンを表示します。材料が足りないなら商品名・必要数・今回の購入単位を、素材がそろっているなら実際の品質確率を案内します。準備を進めると、次の工程へ表示が切り替わります。

- 「まず肉を5個仕入れる」→必要な数量が入力された仕入れ画面。
- 「まんぷく弁当 C以上は○%」→その商品の製法標準化。確率を承知して製造する選択肢は「必要な準備」にもあります。
- 「今回の最高はC、要求はB」→素材の生産技術・仕入れ品質を育てる方法。
- 「研究Pが足りない」「受注枠が満杯」→不足数と、研究Pの増える閉店予定や受注中の注文。

一括準備が可能な注文は、従来どおり「受けて、作って、お届け」で進められます。材料が未確定の段階では、品質成功率を推測の確定値として表示しません。

## いつもの商品を別の目的へ：食卓企画（v58）

6日目または会社Lv3から、ホーム・「取引→顧客」に招待状が届きます。ピクニック、読み聞かせ、仕事仲間の食卓、旅の思い出の4企画。それぞれ2つの用途から好きな場面を選べます。

1. 場面を選ぶ。期限はなく、同時に1つだけ進行します。選ぶだけでは費用も作業枠も使いません。
2. 完成品2種類と届け方を選ぶ。特徴の組み合わせと用途への適合で評価が変わり、提出前に点数と理由が分かります。
3. 料理が足りなければ「お題に合う料理を用意する」→商品を選ぶ→「材料からまとめて用意する」。通常の費用・材料・枠で在庫1個まで準備し、献立へ戻ります。
4. 納得したら「この献立を届ける」。各1個を消費し、お客さまの感想と献立を保存します。企画の提出自体に追加の現金・作業枠は不要です。

品質は100点中12点。用途に合うパンとサラダなら、E品質でも88点に届く例があります。高級品だけが正解にはなりません。オリジナル料理も選べます。

企画の初回に研究P20〜40、採用した各商品の熟練＋3。再挑戦は任意で追加報酬はなく、最高評価の献立を記録します。提出するまでは通常の在庫なので鮮度は進みます。企画そのものは期限なしで、中断・見送りに損失はありません。新しい通貨や毎日の必須作業はありません。

## 基本の操作

| 主タブ | できること |
|---|---|
| ホーム | 動く会社風景、今日できること、閉店予定、目標、日次報告 |
| 製造 | おまかせ、生産、仕入れ、加工、在庫、オリジナル商品 |
| 取引 | 候補と受注済み契約、資金繰り、顧客、卸売、地域 |
| 育成 | スタッフ、求人、研究、品質改善、施設、自動化、経営投資 |
| その他 | 図鑑、大会、ライバル、年表、設定 |

日付は「翌日へ」を押したときだけ進みます。閉じている間に収穫・腐敗・納期失敗は発生しません。

- 生産枠と加工枠は別です。バッチの上限個数を超える場合は別の枠を使います。
- 在庫は入庫ごとのロットです。初期は3営業日使用でき、期限日の営業終了後に残りを廃棄します。
- 受注は1日3件まで。候補の見送りにはペナルティがありません。
- 材料をそろえるだけでは納品完了になりません。「納品する」または許可した自動納品が必要です。
- 品質保証にも素材上限があります。E素材中心なら最高C。製造前の計画で確率と条件を確認できます。
- スタッフは効果使用後、その日は担当固定。配置変更は翌日に予約します。
- 資金がなくなったらホームの案内、または「取引→資金繰り」へ。受託作業・再建支援・余剰在庫買取を使えます。

## 資金が足りないとき（v57）

資金が少なくなるとホームに「会社を立て直そう」が表示されます。「取引→資金繰り」からいつでも次の方法を使えます。

| 方法 | 内容 | 制約 |
|---|---|---|
| 地域の受託作業 | 材料・先払い不要。加工1枠で220円。複数枠をまとめて実行 | 通常の加工枠を使用。使い切った枠は翌営業日に回復 |
| 不足分だけ自動受託 | 閉店時、注文の仕事の後に余った枠で現金を補う | 任意ON。目標500〜3,000円、初期1,200円。試作用に残す枠を守る |
| 協同組合の再建支援 | 返済不要の1,000円。受領日を含む3営業日は日次費用免除 | 資金500円以下、7営業日に1回。材料費・加工費は通常通り |
| 余剰在庫の買取 | 原価を下回る価格で在庫を現金へ戻す | 1日10個まで。予約・保護・期限切れ・価格0のロットは対象外 |

受託は倉庫満杯でも利用できます。資金も材料も作業枠もなくなった日は、支援を受けて翌日へ進み、回復した枠で注文に取り組めます。支援の再利用待ちでも受託は使えます。借金・スタッフの消失・実時間の待機はありません。

受託収入は営業損益へ計上します。支援金は現金を増やしますが、販売利益・営業損益・会社経験へ加算しません。毎日の経営は通常の注文が中心です。

## 求人で仲間を探す（v57）

固定の購入一覧をやめ、「育成→求人」で募集したときだけ応募者が現れる方式にしました。初期スタッフのみのりと既に在籍している仲間はそのまま残ります。

| 募集方法 | 募集費 | 応募人数 | 通常枠の確率：通常／レア／激レア／伝説 | 1人目の保証 |
|---|---:|---:|---|---|
| 町のチラシ | 300円 | 2人 | 80%／18%／2%／0% | なし |
| 求人サイト | 1,200円 | 3人 | 50%／38%／11%／1% | レア以上 |
| ネット求人広告 | 3,000円 | 4人 | 22%／48%／26%／4% | レア以上 |
| テレビCM | 6,500円 | 6人 | 5%／35%／48%／12% | 激レア以上 |

保証枠は、そのレアリティ以上に確率を絞って再配分します。1人目の実確率もゲーム内で確認できます。上表はプレイテスト前の初期調整値です。

1. 全職種から探すか、農家・職人・営業・研究員・物流のいずれかに絞ります。
2. 募集方法を選び、費用・残る資金・未採用候補の入れ替えを確認します。
3. 応募者の5能力・特技・採用後の生産量や倉庫容量の変化を見比べ、採用します。

募集費に採用費を含むため、採用時の追加料金は0円。採用人数に応じ、日次費用は1人につき10円増えます。全員採用する義務はありません。在籍上限は通常16人、ふたりの品評会は2人です。旧セーブで上限を超えている場合も仲間を削除しません。

候補者の名前・能力・特技・外見は募集時に確定し、次の募集まで待ってくれます。日付更新や再読み込みで再抽選しません。募集は1営業日1回。職種を指定しても名前や能力はランダムです。高レアほど主能力の範囲が上がりますが、特技・副能力・配置との相性にも違いがあります。

採用後は「育成→スタッフ」で全能力・配置・研修・履歴を確認できます。「畑の名人」が収穫した当日、「パンへの情熱」の職人が工房にいるとパン類の品質分布が改善し、新しい仲間でも連携が発動します。

## 日を進める前に分かること（v56）

ホームと「翌日へ」の確認画面に、残りの生産・加工枠、今すぐ納品できる注文、材料から準備できる注文、対応可能な新しい候補を表示します。「任意の成長」を開くと、現在の資金・研究Pで選べる研究・設備・採用などへ進めます。各候補はそれぞれ単独で可能という意味で、共通の資金や枠を使えば残りの候補も変わります。

「閉店すると進むこと」には、スタッフが納品する注文、追加の準備費用、研究P、停止理由を表示。閉店時の処理を状態の複製で計算し、自動納品で使い切る商品の廃棄を誤って警告しません。「自動納品ON」でも間に合わない注文は警告します。

普通の日は翌朝のホームに戻り、短い結果と日次報告を残します。毎回詳しい決算を開きたい場合は「その他→設定」で切り替えられます。契約失敗・大会結果・初回評価は結果画面を開きます。

## 毎日の収穫・加工を任せる（v56）

「製造→おまかせ」で、次のどれかを選ぶだけで始められます。

| 任せ方 | 行う仕事 |
|---|---|
| 注文を全部任せる | 受注済みを納期順に収穫・仕入れ・加工・納品。残っている作業枠を使用 |
| 試作の余力を残す | 加工1枠を自分用に残し、それ以外で注文の仕事を進める |
| 自分で進める | おまかせを停止し、手作業や注文ごとの一括操作で進める |

上の2つは1日1,200円の準備予算・標準製造・定番在庫の追加仕込みなし。不要な定時の畑収穫も停止します。購入済みの自動設備は別設定です。注文がなければ、注文用の材料を勝手に増産しません。既存のおまかせ設定は、選び直すまで保持されます。

- 新しい注文を選ぶのはプレイヤーです。日付は自動で進みません。
- 追加の設備費・委任料はありません。通常の材料費と加工費、手動と共通の生産枠・加工枠を使います。
- 予算・目標在庫・製造方針などは「細かく調整する」にまとめました。通常は開かなくても使えます。
- 「この仕事を今進める」と閉店時の作業は同じ1日予算を共有します。
- 保護中の素材・別注文の予約・仕入れ単位・倉庫上限を守ります。レア素材への置き換えや新規受注は行いません。
- 品質を保証できない挑戦案件や、予算・枠・容量が足りない仕事では停止理由を表示します。条件を無視して全部納品する設定ではありません。
- 完成するバッチ単位で準備し、完成分は注文に予約します。複数日に分けられますが、鮮度・納期は通常通りです。
- 注文カードの「受けて、作って、お届け」は、その1件だけをすぐ完了する一括操作。日次おまかせがOFFでも使えます。
- 手元の完成品で複数件を納品できる場合は、「まとめて届ける」も使えます。同じ在庫を二重に数えません。

## オリジナルレシピの食材相性（v55）

相性は、とても悪い−3／悪い−2／少し悪い−1／未知・中立0／少し良い＋1／良い＋2／とても良い＋3の7段階です。選んだ食材のペア点を合計し、**合計×4（最大±24）を品質抽選値へ加えます。合計が−1〜＋1なら、さらに−8〜＋8の整数を均等に抽選して加えます。**

例：小麦粉＋牛乳は＋3なので補正＋12。小麦＋野菜は0で、偶然補正−8〜＋8。菓子＋惣菜は−3なので補正−12。食材を一体の料理にした場合のゲーム内評価であり、現実の食品安全や献立の相性ではありません。

品質抽選値は0.0〜99.9。正の補正は高品質寄り、負の補正は低品質寄りに動かします。最終値を範囲内に収め、研究・素材・職人から求めた品質分布に当てはめます。**素材上限と獲得済み保証を超えて変動しません。**

同じ食材の増量、牛乳＋濃厚ミルクなど同系統の重複ではペア加点を増やしません。配合画面に合計と理由、試作確認画面に補正込みの品質確率、試作結果と商品の歩みに実際の抽選・補正を記録します。完成度は製法の理解、ロット品質は今回の仕上がりとして分けます。

## 音・アニメーション

工房・収穫・配送の動き、製造時の商品演出、品質更新や受賞の演出があります。施設や担当スタッフ、季節、看板商品、地域進出に応じて会社風景が変わります。

BGMは初期状態で0%、効果音は35%です。「その他→設定」で個別の音量、消音、動きを減らす設定、演出短縮を選べます。音が出ない場合は、ゲーム内を一度タップしてから設定を確認してください。

## 保存・バックアップ

- 通常操作後に、このブラウザのlocalStorageへ自動保存します。
- 成功した保存の直前の状態をバックアップに保持します。
- 保存が失敗したら、未保存の状態を保持して進行を停止します。再保存するかJSONを書き出してください。
- 別タブの更新を検出したら、古い状態での上書きを停止します。複数タブで同時に操作しないでください。
- 「その他→設定→全会社をJSONに書き出す」で、ダウンロード・対応端末の共有メニュー・全文コピーを選べます。保存先にファイルができたことを確認してください。
- 読み込みはJSONファイル選択・全文貼り付けに対応します。インポートは現在の会社を消さず、別会社として追加します。会社切り替えも同じ設定画面です。
- ブラウザの履歴・サイトデータの削除、別ブラウザ、別の公開ホスト・端末への移動では保存領域が変わります。移動前に書き出してください。
- 保存不能な環境では、一時プレイと手動書き出しを選べます。終了前の書き出しが必要です。

## v58以前からの引き継ぎ

v58の資金・在庫・契約・スタッフ・求人候補・研究・レシピ・初回評価・乱数・おまかせを保持し、案内と便りの記録を追加します。保存キーとスキーマ3を維持し、ルール2.4.0・コンテンツ59.0へ更新します。過去の納品件数は維持、個数は更新後から集計。営業途中で更新した日の報告にも「個数は更新後」と表示します。

以前の会社では案内を省略状態で開始。すでに過ぎた日の便りをまとめて押し付けず、現在日以降の便りから進みます。v57以前は求人・資金繰り・食卓企画などの既存移行を順番に経由します。支援金や過去のレベル祝い金を再支給しません。

更新前に「設定→全会社をJSONに書き出す」でバックアップを保管してください。更新後のセーブはv59で使用し、古い版へ戻して読み込まないでください。異なるルール版の同じシードでは、以降の結果が変わることがあります。

### GitHub Pagesのゲームを更新する

1. 更新前のゲームからJSONバックアップを書き出す。
2. v59 ZIPを展開し、その中の **index.html** を、GitHubで公開している同じ場所のindex.htmlに置き換えてコミットする。
3. Pagesの更新完了後、今までと同じゲームURLを再読み込み。設定画面の「ゲームv59」を確認する。

ZIPそのものを置いてもゲームは更新されません。同じURL・同じブラウザなら既存のlocalStorageを引き継ぎます。サイトデータを消す必要はありません。ここに同梱した版の提供だけでは、あなたのGitHubリポジトリは更新されません。

### v52の場合

同じ保存領域にv52のデータがあれば、開始画面に引き継ぎボタンが出ます。JSONファイルをお持ちなら、開始画面または設定から読み込めます。v52側に書き出しボタンがない場合は、同梱の `v52-save-export.html` をv52と同じホストで開くと、元データを書き出せます。この補助ページは元のセーブを変更しません。

移行は元のv52保存キーを上書きせず、v53の別セーブを作ります。元データも移行後の会社に保持し、設定から取り出せます。

数量・品質が不一致の在庫は、数量表を上限として高品質から保持します。不明な期限・素材由来は推定として移行ログへ記録します。受注済み契約には最低2営業日の猶予を付けます。旧大会予約は旧予定日・提出品質を保持します。旧実績・顧客評価・受賞履歴の原記録も移行アーカイブで参照できます。

実際のユーザーのセーブファイルによる移行確認は未実施です。v52の実ソースに基づく合成データで確認しています。

## 60日後と再挑戦

60日目の営業結果まで含めて評価します。初回評価を保存し、希望した場合だけ61日目へ進みます。継続期は60日ごとに、前回からの変化を含む評価を残します。

別シナリオは元の会社を消さず開始できます。小さな倉庫、高級少量生産、町内の定番食、スタッフ2人の品評会があります。共通プロフィールには称号・発見レシピ・評価履歴を残し、資金や能力倍率は引き継ぎません。同じ初期シードとルール版で再挑戦できます。
